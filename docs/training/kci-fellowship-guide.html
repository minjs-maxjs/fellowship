혼자 일해도 열 명이 함께합니다

KCI 원정대는 Claude Code 안에서 움직이는 AI 팀입니다. 오케스트레이터 민준수가 일을 받아 크기를 가늠하고, 기획·설계·개발·리뷰·보안·테스트·배포·디자인·문서를 맡은 아홉 동료에게 나눠 맡깁니다.

일의 무게에 따라 부르는 인원이 달라집니다

민준수는 모든 요청을 네 단계로 분류합니다. 경계가 애매하면 낮은 단계를 고릅니다. 혼자 일하는 사람의 시간이 가장 귀하기 때문입니다.

TIER 1

민준수 혼자 처리

오타 수정, 짧은 질문처럼 바로 끝나는 일. 추가 비용 없음.

TIER 2

스킬 하나 또는 팀원 한 명

새 컴포넌트 하나, 버그 하나. 필요한 전문가 한 명만 부릅니다.

TIER 3

순서대로 이어 달리기

여러 파일에 걸친 리팩터링. 앞사람 결과가 다음 사람 입력이 됩니다. 약 3–5분.

TIER 4

재호 검토 후 병렬 투입

기능 하나 전체. 재호가 범위를 먼저 잠그고, 여러 팀원이 동시에 움직입니다. 약 8–15분.

중요한 코드는 승인될 때까지 리뷰합니다

주혁 구현→승현 리뷰→문제 발견 시 주혁 수정→승현 재리뷰→승인되면 완료

로그인·결제·데이터 변경·공개 API 같은 위험 경로에 적용됩니다. 승현은 코드를 직접 고치지 않고 지적만 하며, 한 번 시작한 리뷰는 승인될 때까지 이어집니다. 지적 사항은 Critical(버그·보안·데이터 손실), Important(구조·누락·테스트 공백), Minor(스타일·문서)로 나뉩니다.

팀원 소개

열 명이 각자 맡은 일과 코드 위치

팀원마다 정의 파일 한 개(agents/이름.md)에 성격, 역할, 작업 방식, 보고 형식이 모두 들어 있습니다. 도구는 필요한 것만 줍니다. 리뷰어와 보안 담당은 파일을 고칠 수 없습니다.

사용법

설치부터 첫 작업까지

설치하기

Claude Code를 열고 아래 두 줄을 차례로 입력합니다.

/plugin marketplace add minjs-maxjs/fellowship
/plugin install fellowship@fellowship

프로젝트에 원정대 설정하기

원정대를 쓸 프로젝트마다 한 번씩 /fellowship:start로 기본 틀을 만들어 줍니다. 예를 들어 창고관리시스템 프로젝트라면 이렇게 입력합니다.

주인공/fellowship:start D:\PYthon프로그램들\창고관리시스템 이 프로젝트에 Fellowship을 설정해줘

그러면 민준수가 다음 순서로 진행합니다.

  1. 지식 그래프 먼저. graphify가 설치돼 있는지 확인합니다. 설치돼 있으면 "프로젝트 지식 그래프부터 만들까요?"라고 묻고, 예라고 하면 /fellowship:graph가 실행됩니다. 설치돼 있지 않으면 설치 방법을 두 줄로 안내하고 그대로 다음 단계로 넘어갑니다. 선택 사항입니다.
  2. 폴더 틀 만들기. 프로젝트 안에 docs/fellowship/를 만들고 그 아래에 사양서·계획·인수인계·디자인 폴더와 보관함(archive)을 둡니다.
  3. 기본 문서 만들기. 퀘스트 로그(quest-log.md), 지난 로그 보관(quest-log-archive.md), 제품 설명(product.md), 폴더 안내(README.md)를 만듭니다.
  4. 제품 질문. "무엇을, 누구를 위해 만드나요?"라고 묻습니다. 예: "자재 입출고와 재고를 관리하는 사내 시스템이고, 사용자는 창고 담당자와 구매팀이야." 답이 product.md에 들어가며, 이 답이 채워지기 전에는 팀원을 부르지 않습니다.
  5. 코드 지도 제안. "코드 지도를 지금 만들까요?"라고 묻습니다. 예라고 하면 /fellowship:map이 이어서 실행됩니다. 몇 분 걸리지만 Tier 3 이상 작업은 이 지도를 바탕으로 움직입니다.
창고관리시스템/
└─ docs/fellowship/
   ├─ quest-log.md          진행 중인 결정과 할 일
   ├─ quest-log-archive.md  오래된 로그 보관
   ├─ product.md            무엇을, 누구를 위해 만드는지
   ├─ README.md             이 폴더 안내
   ├─ specs/  plans/  handoffs/  design/
   └─ archive/ (specs, plans, handoffs, design)

팁. 가장 확실한 방법은 Claude Code를 창고관리시스템 폴더에서 연 다음 /fellowship:start만 입력하는 것입니다. 명령은 지금 열린 프로젝트를 기준으로 동작하기 때문입니다. 이미 docs/fellowship/가 있으면 덮어쓰지 않고, 빠진 것만 채울지 먼저 묻습니다.

이후에는 그 폴더에서 세션을 열 때마다 민준수가 먼저 퀘스트 로그를 읽고 지난 작업을 이어받습니다. 민준수가 인사하지 않으면 플러그인이 로드되지 않은 것입니다. 다른 오케스트레이터 플러그인(Superpowers 등)과 함께 켜 두면 인격이 충돌하니 하나만 켜 두세요.

평소 말하듯 일을 맡기기

누구를 부를지는 민준수가 정합니다. 그냥 하고 싶은 일을 말하면 됩니다.

로그인 화면 오타 고쳐줘Tier 1 · 민준수가 바로 처리
이 버그 원인 찾아줘Tier 2 · investigate 스킬로 원인 분석
주문 모듈 구조 정리해줘Tier 3 · 현수 설계 → 주혁 구현 → 승현 리뷰
정기 결제 기능 추가하자Tier 4 · 재호 범위 정의 후 여러 명 병렬 투입

명령어 한눈에 보기

평소에는 명령 없이 말로 맡기면 충분합니다. 명령은 특정 작업 방식이나 특정 팀원의 관점을 지금 대화에 바로 불러오고 싶을 때 씁니다. 모든 명령은 /fellowship:으로 시작합니다.

팀원 직접 부르기

팀원 이름 명령은 그 팀원을 별도로 출동시키는 것이 아니라, 그 팀원의 작업 방식과 관점을 지금 대화에 불러오는 것입니다. 짧게 의견을 듣거나 한 가지 관점으로 검토받을 때 좋습니다. 큰 작업은 그냥 말로 맡기면 민준수가 알맞은 팀원을 따로 출동시킵니다.

함께 쓰는 도구

graphify로 프로젝트를 지도처럼 보기

graphify는 폴더 안의 코드와 문서를 읽어 "무엇이 무엇과 연결되는지"를 지식 그래프로 만들어 주는 도구입니다. 처음 보는 프로젝트를 파악하거나, 어떤 기능을 고치기 전에 영향을 받는 곳을 찾을 때 유용합니다. 원정대 플러그인과는 별도로 설치하는 도구이며, 둘을 함께 쓰면 민준수와 팀원들이 그래프를 근거로 코드 구조를 답합니다.

설치하기 (PC마다 한 번)

Python이 설치된 PC의 터미널(PowerShell)에서 실행합니다. 두 번째 줄이 Claude Code에 /graphify 명령을 등록합니다.

pip install graphifyy
graphify install

패키지 이름은 graphifyy(y 두 개)입니다. 설치 후 Claude Code를 새로 열면 /graphify를 쓸 수 있습니다.

그래프 만들기

주인공/graphify D:\PYthon프로그램들\창고관리시스템

원정대 안에서는 /fellowship:graph를 입력해도 됩니다. 설치 여부를 확인한 뒤 그래프가 없으면 새로 만들고, 있으면 바뀐 파일만 갱신하며, graphify-out/을 .gitignore에 넣을지도 물어봅니다.

주인공/fellowship:graph

어느 쪽이든 경로를 생략하면 지금 열린 폴더를 분석합니다. 끝나면 프로젝트 안에 graphify-out/ 폴더가 생기고 세 가지 결과물이 들어갑니다.

파일내용
graph.html브라우저로 여는 인터랙티브 그래프. 점을 눌러 연결 관계를 따라갈 수 있습니다.
GRAPH_REPORT.md사람이 읽는 요약 보고서. 가장 많이 연결된 핵심 요소, 뜻밖의 연결, 던져 볼 만한 질문을 정리해 줍니다.
graph.json그래프 원본 데이터. 이후 질문에 답할 때 이 파일을 씁니다.

그래프에 질문하기

그래프가 한 번 만들어지면 다시 분석하지 않고 바로 답합니다. 원정대 프로젝트에 그래프가 있으면 세션을 열 때 플러그인이 민준수에게 알려 주고, 민준수·현수·주혁·승현은 구조나 영향 범위를 물으면 grep보다 그래프를 먼저 조회합니다. /fellowship:map도 GRAPH_REPORT.md를 먼저 읽습니다.

명령하는 일입력 예시
/graphify query질문과 관련된 부분을 넓게 훑어 답합니다./graphify query "출고 처리는 어떤 흐름으로 돌아가?"
/graphify path두 요소가 어떤 경로로 연결되는지 보여 줍니다./graphify path "출고등록" "재고테이블"
/graphify explain요소 하나를 쉬운 말로 설명하고 이웃을 보여 줍니다./graphify explain "InventoryService"
/graphify --update바뀐 파일만 다시 분석해 그래프를 갱신합니다./graphify . --update

/fellowship:map 과의 차이

  • /fellowship:map은 영학이 쓰는 요약 문서입니다. 스택, 구조, 관례, 위험 지점을 글로 정리합니다.
  • graphify는 파일·함수·문서 사이의 연결 관계를 그래프로 남깁니다. "이걸 고치면 어디가 영향받지?"에 강합니다.
  • 둘 다 만들어 두면 좋습니다. 큰 그림은 map, 세부 연결은 graphify.

비용과 속도

  • 코드는 구문 분석으로 처리해 AI 사용량이 들지 않고 빠릅니다.
  • 문서·이미지가 섞여 있으면 Claude가 직접 읽어 정리하므로 사용량이 들고 시간이 더 걸립니다.
  • 별도 API 키는 필요 없습니다.

주의할 점

  • graphify-out/은 프로젝트 폴더 안에 생깁니다. 저장소에 올리지 않으려면 .gitignore에 graphify-out/을 추가하세요. 내 PC 경로가 들어 있습니다.
  • 파일이 500개를 넘으면 하위 폴더를 골라 나눠 분석하라고 안내합니다.
  • 코드를 크게 바꾼 뒤에는 --update로 갱신해야 답이 정확합니다.
코드 지도

저장소는 이렇게 생겼습니다

폴더들어 있는 것
agents/팀원 9명의 정의 파일. 역할, 성격, 작업 방식, 보고 형식이 한 파일에 모두 있습니다. references/에는 문서 템플릿과 체크리스트가 있습니다.
skills/여러 팀원이 함께 쓰는 작업 방법 12종. 민준수 자신도 using-fellowship 스킬입니다.
commands/슬래시 명령 19개. 대부분 스킬이나 팀원 역할을 불러오는 입구입니다.
hooks/자동 실행 스크립트. 세션 시작 시 문맥 주입, 파일 수정 전 계획 확인, 문맥 사용량 감시, 세션 종료 시 정리.
evals/팀원별 평가 시나리오. AutoImprove가 이걸로 지시문을 스스로 개선합니다.
tests/훅 동작을 검증하는 Node.js 테스트 130개.
docs/fellowship/퀘스트 로그, 제품 맥락, 설계 기록. 세션이 바뀌어도 팀이 기억을 이어가는 곳입니다.

모든 훅은 Node.js 표준 라이브러리나 bash로만 작성됐습니다. 외부 서비스 호출이나 추가 의존성이 없어 사내 PC에서 그대로 돌아갑니다. 다만 docs/fellowship/의 문서는 매 세션 AI에게 주입되므로, 소스 코드와 같은 수준으로 관리해야 합니다.

플러그인을 움직이는 AI 모델(Claude)은 Anthropic의 서비스이며, 사용 조건은 각자의 Claude 이용 약관을 따릅니다. 이 플러그인의 MIT 라이선스는 플러그인 코드에만 적용됩니다. 함께 소개한 graphify(graphifyy 패키지)는 별도의 오픈소스 도구로 Apache-2.0 라이선스를 따르며, 각자 PC에 따로 설치합니다.

왜 써 볼 만한가

KCI 원정대가 자랑할 만한 점

역할이 나뉜 진짜 팀

일반 AI 비서는 혼자 다 합니다. 원정대는 만드는 사람과 검사하는 사람이 다릅니다. 리뷰어와 보안 담당은 아예 파일을 고칠 권한이 없어, 자기 코드를 자기가 통과시키는 일이 없습니다.

필요한 만큼만 부름

오타 하나에 열 명을 부르지 않습니다. 4단계 분류 덕분에 작은 일은 빠르고, 큰일만 제대로 무겁게 처리합니다.

세션이 바뀌어도 기억

퀘스트 로그와 팀원별 메모리가 남아 다음 날 열어도 어제 하던 일을 이어갑니다.

스스로 나아지는 지시문

팀원마다 평가 시나리오가 있고, AutoImprove가 점수를 재며 지시문을 한 번에 하나씩 고칩니다. 과적합을 막는 홀드아웃 검증도 따로 둡니다.

내 PC에서만 동작

훅은 외부로 아무것도 보내지 않습니다. 사내 코드에 써도 플러그인 자체가 데이터를 내보낼 걱정은 없습니다.

우리 팀의 얼굴

팀원 이름과 이야기가 KCI 사람들입니다. 누가 무슨 일을 하는지 외우기 쉽고, 쓰는 재미가 있습니다.
